# TVBreakEven

TradingView 推保测试插件。

目标：开仓后，由你指定一个触发价；当 TradingView 当前价格触及触发价时，把止损推到成本价附近。

## 当前版本定位

这是第一版测试工具。

优先支持：

```text
TradingView + Tradovate
单笔持仓
手动输入触发价
图表水平线选触发价
推保价由你填开仓价
触发后只处理一次
保留日志
```

也可以在 TradingView Paper Trading 页面测试监控和报警逻辑。

## 触发后只处理一次是什么意思

比如多单：

```text
触发价 = 4568.5
当前价格第一次 >= 4568.5
```

插件会立刻把状态标记为 `已触发`，并停止本次监控。

这样做是为了避免价格在触发价附近来回跳动时，插件每秒重复报警、重复点击、重复修改止损。

如果你想重新监控，需要再次点击 `启动监控`。

## 执行方式

### 辅助模式

触发后弹窗报警，告诉你应该把止损推到哪个价格。

这是最稳的测试模式。

### 自动模式

触发后尝试在 TradingView 页面里找到止损元素，并尝试进入可输入状态后修改价格。

这一块依赖 TradingView 页面结构，第一版不能保证所有账号、所有经纪商连接、所有语言环境都 100% 成功。

如果自动模式失败，插件会报警，让你手动处理。

## 使用方式

1. 打开 TradingView 图表页面。
2. 连接 Tradovate 或 Paper Trading。
3. 开仓并确认 TradingView 页面能看到持仓和止损。
4. 打开插件 `TVBreakEven`。
5. 选择方向：

```text
多单 Long
空单 Short
```

6. 填写：

```text
触发价
推保价
```

推保价通常填开仓价。当前版本如果没有稳定识别到 TradingView 的开仓价，不会自动乱填，必须手动填写。

7. 点击 `启动监控`。

## 图表选价

点击 `图表选价` 后，TradingView 页面上会出现一条黄色虚线。

拖动虚线到你想要的触发价即可。

插件会实时把该价格写入 `触发价`，水平线会一直留在图表上，方便你二次修改。

注意：第一版水平线价格是根据当前页面可见价格和画布高度估算出来的，适合快速测试。后面如果需要更精确，可以专门适配 TradingView 的价格轴。

## 读取当前页

`读取当前页` 是调试按钮。

它会让插件立刻读取当前 TradingView 页面，并更新：

```text
当前价格
识别信息
调试信息
日志
```

如果你看到当前价格不对、页面识别不对、或者触发没有反应，先点这个按钮，然后复制 `调试信息` 发给 Codex。

## 识别信息、日志、调试信息

`识别信息` 是简化后的页面识别结果。

`日志` 是操作日志，例如启动、停止、触发、提醒。

`调试信息` 是给排查问题用的完整信息，包含：

```text
当前输入框里的值
storage 里的配置
最近一次识别到的价格
价格来源文本
最近一次页面识别结果
最近的日志
最近的调试事件
```

这三个区域都有 `复制` 按钮。遇到问题时，优先复制 `调试信息`。

## 报警方式

当前 Chrome 插件会使用两种提醒：

```text
Chrome 桌面通知
TradingView 页面内 alert 弹窗
```

TradingView 指标不能直接接收 Chrome 插件传来的消息，也不能替 Chrome 插件转发报警。

如果需要手机报警，后面更稳的方式是：

```text
Chrome 插件 -> 本地 bot / webhook -> 手机通知
```

也可以继续使用 TradingView 指标负责策略信号报警，Chrome 插件只负责推保监控和页面执行。

## 重要限制

```text
Chrome 关闭后不会运行
TradingView 页面关闭后不会运行
电脑睡眠后不会运行
TradingView 页面结构变化可能导致自动模式失败
自动模式失败时需要手动移动止损
```

这个工具不替代真正的交易 API 风控。

## 文件说明

```text
manifest.json
Chrome 插件声明。

popup.html / popup.css / popup.js
插件弹窗界面、设置、日志和操作按钮。

content.js
运行在 TradingView 页面里，负责水平线、价格读取、触发监控和推保执行器。

background.js
负责浏览器通知。
```
